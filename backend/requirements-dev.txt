# Test/development dependencies. Install with:
#   pip install -r requirements-dev.txt
# This pulls in requirements.txt too, so this one file is sufficient to
# both run the API and run the test suite in a clean environment.
#
# Root cause this file fixes: pytest was not declared as a project
# dependency anywhere (no requirements-dev.txt, no dev section in
# requirements.txt, no pyproject.toml/setup.cfg). An environment that
# happened to have `pytest` available globally but had never run
# `pip install -r requirements.txt` for this project would fail with
# "ModuleNotFoundError: No module named 'jose'" the moment a test
# imported anything from src/ — not because python-jose is missing from
# requirements.txt (it isn't — see python-jose[cryptography] below,
# already present there and confirmed working via a from-scratch venv
# install), but because pytest and the project's own runtime
# dependencies were never guaranteed to be installed together.
-r requirements.txt
